# 배포 / 호스팅 (무료)

> 이 가이드를 따르면 회사의 다른 분들도 **다른 컴퓨터에서 같은 데이터·승인 카드**를 볼 수 있는 상태가 됩니다. 모든 서비스는 무료 티어로 구성됩니다.

전체 흐름은 이렇습니다.

```
HubSpot (개발자 테스트 계정, 무료)
       │ 웹훅
       ▼
Render Web Service (FastAPI BE, 무료)
       │
       ├──► Supabase Postgres (DB, 무료 500MB)
       │
       ├──► Anthropic API (LLM, 종량제 ~$3–10/월)
       │
       └──► Slack/Teams (승인 카드, 무료)
```

총 4단계:

1. **HubSpot 개발자 계정 + 테스트 계정 + Private App 토큰 만들기**
2. **Supabase 프로젝트 생성하고 Postgres URL 받기**
3. **Render에 백엔드 배포 + 환경변수 입력**
4. **연결 검증 (헬스체크 + 인바운드 end-to-end 테스트)**

---

## 1단계 — HubSpot 개발자 계정과 테스트 계정 만들기

### 1-1. 개발자 계정 가입

1. https://developers.hubspot.com 접속 → **Create developer account** 클릭.
2. 회사 이메일로 가입. (무료, 신용카드 불필요)
3. 가입 후 좌측 메뉴 **Apps** → **Test accounts**.

### 1-2. 테스트 계정 생성

1. **Create test account** 버튼 클릭.
2. 이름 입력 (예: `Sales Automation QA`).
3. 생성된 테스트 계정 URL을 북마크 — 이게 우리가 인바운드를 흘려보낼 가짜 HubSpot 환경입니다.

### 1-3. Private App 토큰 발급 (테스트 계정 안에서)

1. 테스트 계정에 로그인 → 우측 상단 톱니바퀴 (**Settings**) → 좌측 **Integrations** → **Private Apps**.
2. **Create a private app** 클릭.
3. **Basic Info** 탭: 이름 `Sales Automation BE` 정도로.
4. **Scopes** 탭에서 다음을 체크:
   - `crm.objects.contacts.read`
   - `crm.objects.contacts.write`
   - `crm.objects.deals.read`
   - `crm.objects.deals.write`
   - `crm.objects.companies.read`
   - `sales-email-read`
   - `tickets`
   - (있으면) `crm.objects.emails.read`, `crm.objects.emails.write`
5. **Create app** → 확인창에서 **Continue creating** → 토큰이 표시됩니다.
6. **이 토큰을 안전한 곳에 복사**해두세요. 다시 볼 수 없으므로 분실 시 새로 발급해야 합니다.

> `.env` 의 `HUBSPOT_PRIVATE_APP_TOKEN=` 에 이 값을 넣게 됩니다.

### 1-4. 로컬에서 토큰 검증 (선택, 권장)

이 시점에 한 번 로컬에서 토큰이 동작하는지 확인하세요:

```powershell
# .env 에 HUBSPOT_PRIVATE_APP_TOKEN 넣은 뒤
.venv\Scripts\python.exe scripts\test_hubspot_inbound.py --dry-llm
```

`--dry-llm` 옵션은 LLM을 호출하지 않고 토큰·DB만 검증합니다. 마지막에 `[DONE] 인바운드 end-to-end 테스트 통과.` 가 보이면 1단계 성공.

## 2단계 — Supabase Postgres 만들기

### 2-1. 가입과 프로젝트 생성

1. https://supabase.com → **Start your project**.
2. GitHub 또는 이메일로 가입 (무료).
3. **New project** 클릭.
4. 필드 입력:
   - Project name: `sales-automation`
   - Database password: 강한 문자열 (저장해두세요!)
   - Region: `Northeast Asia (Seoul)` 또는 `Northeast Asia (Tokyo)` — 한국 사용자라면 가장 가까운 곳.
5. **Create new project** → 약 2–3분 대기.

### 2-2. Postgres 연결 URL 복사 (⚠️ Session Pooler 사용)

1. 프로젝트 페이지 좌측 **Project Settings** (톱니바퀴) → **Database**.
2. **Connection string** 섹션에서 탭 또는 셀렉터 중 **"Session pooler"** 선택. (**Direct connection 은 IPv4 가 막혀 있어서 한국 ISP 망에서는 안 됩니다.** Transaction pooler 도 가능하지만 SQLAlchemy session pool 과는 Session pooler 가 호환적입니다.)
3. 표시되는 URL 형식 — 사용자명에 프로젝트 ref 가 붙고 호스트가 `pooler.supabase.com` 입니다:
   ```
   postgresql://postgres.<projref>:[YOUR-PASSWORD]@aws-X-<region>.pooler.supabase.com:5432/postgres
   ```
4. `[YOUR-PASSWORD]` 를 위에서 정한 비밀번호로 치환.
5. **반드시 끝에 `?sslmode=require` 추가**:
   ```
   postgresql://postgres.<projref>:<pwd>@aws-X-<region>.pooler.supabase.com:5432/postgres?sslmode=require
   ```

> 이 값이 Render 의 `DATABASE_URL` 환경변수로 들어갑니다.

> **왜 Direct connection 이 아니라 Pooler?** Supabase 가 2024년부터 무료 티어의 Direct connection 을 IPv6 전용으로 전환했습니다. 한국 ISP(Kornet 등) 는 IPv6 outbound 가 제한적이라 DNS 해결은 되지만 connect 가 실패합니다(`could not translate host name`). Pooler 는 IPv4 진입점을 무료로 제공해서 동일 망에서 동작합니다.

### 2-3. (선택) 로컬에서 Postgres 사용 테스트

로컬에서도 같은 DB를 보고 싶다면:

```powershell
pip install -r requirements-postgres.txt
# .env 의 DATABASE_URL 을 Supabase URL 로 바꾸기
.venv\Scripts\python.exe scripts\init_db.py
.venv\Scripts\python.exe -m src.cli healthcheck
```

마이그레이션이 적용되고 `db_connectivity = PASS` 가 나오면 성공.

## 3단계 — Render 배포

### 3-1. GitHub 푸시

Render는 GitHub 저장소를 보고 배포합니다. 아직 안 올렸다면:

1. https://github.com → **New repository** → 이름 `sales-automation` → **Private** 권장.
2. 로컬에서:
   ```powershell
   git remote add origin https://github.com/<당신>/sales-automation.git
   git push -u origin main
   ```

### 3-2. Render 가입과 Blueprint 연결

1. https://render.com → **Sign up with GitHub** (무료).
2. 가입 후 좌측 **Blueprints** → **New Blueprint Instance**.
3. GitHub repo 권한 허용 → `sales-automation` 선택.
4. Render가 자동으로 `render.yaml` 을 인식하고 서비스 한 개(`sales-automation`)를 표시.
5. **Apply** 클릭 → 첫 빌드가 시작됩니다 (약 3–5분).

### 3-3. 환경변수 채우기

Render 대시보드 → **sales-automation** 서비스 → 좌측 **Environment** 탭. 아래 항목을 **하나씩** 입력:

| 변수 | 값 |
|---|---|
| `DATABASE_URL` | 2단계에서 복사한 Supabase Postgres URL |
| `HUBSPOT_PRIVATE_APP_TOKEN` | 1단계에서 받은 토큰 |
| `ANTHROPIC_API_KEY` | https://console.anthropic.com 에서 발급한 키 |
| `SLACK_BOT_TOKEN` | Slack App `Bot User OAuth Token` (xoxb-…) |
| `SLACK_APPROVAL_CHANNEL_ID` | 승인 카드를 보낼 Slack 채널 ID |

> Slack 봇 만들기는 별도 문서가 필요하면 알려주세요. Anthropic 키만 있으면 LLM은 동작합니다.

값을 저장하면 Render가 자동으로 재배포합니다.

### 3-4. 배포 확인

빌드 로그에서 다음이 보이면 성공:

```
Applied X migration(s): 0001_initial, 0002_llm_usage
Build successful
Live ✓ https://sales-automation-xxxx.onrender.com
```

브라우저에서:
```
https://sales-automation-xxxx.onrender.com/healthz
```

`{"status":"ok"}` 가 보이면 BE 서버는 살아있습니다.

## 4단계 — 인바운드 end-to-end 검증

배포된 BE 가 HubSpot 테스트 계정과 실제로 통신하는지 확인합니다.

### 4-1. 헬스체크 (외부에서)

```powershell
curl https://sales-automation-xxxx.onrender.com/healthz
```

(첫 호출은 sleep 에서 깨어나느라 ~30초 걸릴 수 있음 — 두 번째 호출부터는 빠릅니다.)

### 4-2. 로컬에서 인바운드 시뮬레이션 (Render BE 의 DB 를 통해)

`.env` 의 `DATABASE_URL` 을 Supabase URL 로 설정한 상태에서:

```powershell
.venv\Scripts\python.exe scripts\test_hubspot_inbound.py --message "월 사용료가 얼마인가요?"
```

성공하면:
- HubSpot 테스트 계정에 임시 contact 가 만들어졌다가 사라짐.
- Supabase DB 의 `messages` 테이블에 `pending_approval` 한 줄이 생김 (Supabase 대시보드 → Table Editor 로 확인 가능).
- Slack 승인 채널에 카드가 도착함 (Slack 설정 완료된 경우).

### 4-3. (다음 단계) HubSpot 웹훅 연결

여기까지 오면 BE 가 동작하는 게 확인된 상태입니다. HubSpot 이 실제로 우리 BE 로 이벤트를 쏘게 하려면:

1. 테스트 계정 → **Settings** → **Integrations** → **Webhooks**.
2. **Create subscription**:
   - URL: `https://sales-automation-xxxx.onrender.com/webhook/hubspot/inbound`
   - Header: `X-Internal-Token: <Render 가 자동 생성한 INTERNAL_API_TOKEN 값>`
   - Event type: `contact.creation` (먼저 가장 기본)
3. **Subscribe** 후 테스트 계정에서 contact 하나 만들어 보면 BE 로그에 webhook 도착 기록이 남습니다.

n8n 워크플로 import 는 그 다음 단계입니다 (`n8n_workflows/` 의 JSON 을 n8n 인스턴스에 import).

## 다른 분들이 다른 컴퓨터에서 보는 방법

위 단계가 끝나면:

- **데이터**: 모두 Supabase 에 있으므로, 누구든 `DATABASE_URL` 만 알면 SQL Editor 로 조회 가능. Supabase 대시보드의 **Table Editor** 도 누구나 (프로젝트 멤버로 초대된 사람) 사용 가능.
- **승인 카드**: Slack/Teams 채널 멤버라면 누구나 카드 보고 승인 가능.
- **리포트**: 백엔드의 `/run/report?kind=daily` 호출로 생성된 마크다운이 Supabase 의 `events` 테이블 또는 Slack 채널에 들어감.
- **백엔드 직접 호출**: `https://sales-automation-xxxx.onrender.com` + `X-Internal-Token` 헤더로 누구든 API 호출 가능.

팀원 추가 방법:
1. Supabase 프로젝트 → **Project Settings** → **Team** → **Invite** (이메일로 초대).
2. Render Web Service → 좌측 **Access** → 팀원 추가.

## 비용 한도 (월 기준)

| 항목 | 무료 한도 | 초과 시 |
|---|---|---|
| Render Web Service | 500 시간/월 (free) | 한도 도달 후 일시중지, 다음 달 1일 리셋 |
| Supabase Postgres | 500MB, 50K MAU | 일시중지(데이터 보존), Pro $25/월 |
| HubSpot 개발자/테스트 계정 | 영구 무료 | — |
| Slack 무료 워크스페이스 | 메시지 90일 보존 | 카드 자체는 BE DB 에 영구 보존되므로 무관 |
| Anthropic API | 종량제 | ~$3–10/월 (1k 메시지 가정, Sonnet 기준) |

**MVP 사용량에서는 Anthropic API 만 과금**이고 그 외는 전부 $0 입니다.

## 자주 막히는 곳

### "psycopg2.OperationalError: SSL connection has been closed unexpectedly"

→ Supabase Postgres URL 끝에 `?sslmode=require` 가 빠진 경우. URL 마지막에 추가하세요.

### Render 빌드가 `init_db.py` 단계에서 실패

→ `DATABASE_URL` 이 비어 있거나 `postgres://` (잘못된 스킴) 인 경우. `postgresql://` 로 시작하는지 확인. (코드가 자동 변환하긴 하지만 명시적으로 맞춰주는 게 안전합니다.)

### 첫 HubSpot 웹훅 호출이 timeout

→ Render free 인스턴스가 sleep 상태였을 가능성. HubSpot 은 자동 재시도하므로 1–2분 안에 두 번째 시도가 성공합니다. 자주 sleep 되는 게 거슬리면 Render Starter($7/월) 로 업그레이드.

### Anthropic 429 (rate limit)

→ 동시 호출이 너무 많은 경우. 보통 인바운드 자동화 사용량에선 안 발생. n8n 워크플로의 batch size 를 줄이세요.
