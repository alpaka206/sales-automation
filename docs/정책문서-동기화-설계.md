# 왜 정책 문서를 zip 드롭으로 넣는가

> **읽는 이에게.** 이 파일은 "노션 API 쓰면 되는데 왜 안 했지?" 라는 질문에 답하기 위해
> 있습니다. 그 질문은 합리적이고, 답은 "그 API를 쓸 수 없어서" 입니다. 아래는 실제로 시도한
> 것과 각각이 어디서 막혔는지의 기록입니다. **고치기 전에 §5의 확인 절차부터 돌려 보세요** —
> 조건이 바뀌었다면 더 단순한 방법으로 돌아가는 것이 맞습니다.
>
> 최종 확인: 2026-08-04

---

## 1. 한 줄 요약

노션을 읽을 수 있는 기계와 DB에 쓸 수 있는 기계가 **서로 다르고**, 둘을 잇는 자동 경로가
**전부 막혀 있습니다.** 그래서 사람이 파일을 옮깁니다.

```
             노션 읽기    DB 쓰기
서버            ✗           ✓        ← 통합 토큰 발급 불가
담당자 PC       ✓           ✗        ← 사내망이 5432/6543 차단
```

---

## 2. 시도한 것과 막힌 지점

### ① 노션 공식 API (`NOTION_TOKEN`) — 가장 단순하고, 쓸 수 없음

정상이라면 이게 답입니다. 서버가 통합 토큰으로 페이지를 직접 읽고, 콘솔의 `동기화` 버튼만
있으면 됩니다. 코드도 이미 그 형태로 남아 있습니다 — `src/integrations/notion.py` 의
`fetch_page` 가 그것이고, `sync_policy_sources(fetcher=None)` 이면 그 경로를 씁니다.

**막힌 이유**: 회사(ESTsoft) 노션 워크스페이스에서 내부 통합(internal integration)을 만들
권한이 없습니다. 토큰을 발급받을 수 없으므로 `NOTION_TOKEN` 이 영원히 비어 있고,
`notion.is_configured()` 가 False 라 이 경로는 조용히 건너뜁니다.

> **이 조건만 풀리면 나머지는 전부 필요 없습니다.** §5 참고.

### ② 브라우저 쿠키 (`NOTION_TOKEN_V2`) — 절반만 됨

담당자 PC에서 본인 노션 세션 쿠키로 비공개 v3 API(`enqueueTask` → `getTasks`)를 호출해
내보내기를 만들고, 노션이 주는 서명된 URL에서 zip을 받는 방식입니다.
(`src/integrations/notion_session.py`)

**막힌 이유**: 실행 결과입니다.

```
1. enqueueTask (www.notion.so)      →  성공, 서명된 exportURL 반환
2. GET exportURL (file.notion.com)  →  403
   "Access denied! Please ask the owner to share the page with you,
    and log into your account."
```

내보내기 **생성이 성공했다는 것**이 핵심입니다 — 쿠키는 유효하고 계정은 그 페이지를 읽을 수
있습니다. 노션이 파일 호스트를 `file.notion.com` 으로 분리하면서 그쪽은 **별도 쿠키
(`file_token`)** 를 봅니다. 한 작업의 두 단계가 서로 다른 쿠키를 요구합니다.

`NOTION_FILE_TOKEN` 을 지원하도록 코드를 고쳐 두었으므로 두 쿠키를 다 넣으면 동작할 수
있습니다. 그래도 **주된 경로로 삼지 않은 이유**:

- 비공개 API입니다. 노션이 예고 없이 바꿉니다 — 방금 그렇게 깨졌습니다.
- 쿠키는 만료됩니다. 담당자가 주기적으로 다시 복사해야 합니다.
- 쿠키 두 개를 `.env` 에 두는 것은 개인 세션 자격증명을 파일로 보관하는 일입니다.

### ③ 로컬 스크립트가 DB에 직접 쓰기 — 네트워크가 막음

`scripts/sync_notion_local.py` 의 원래 설계입니다. 담당자 PC가 노션을 읽고 그 자리에서
`policy_sources` 에 씁니다.

**막힌 이유**: 사내망이 DB 포트를 막습니다. 실측:

```
aws-1-ap-northeast-1.pooler.supabase.com
  5432 : 차단/타임아웃      ← PostgreSQL
  6543 : 차단/타임아웃      ← Supabase 트랜잭션 풀러
   443 : 열림
```

같은 호스트인데 443만 열립니다. DNS도 라우팅도 아닌 **포트 기반 아웃바운드 규칙**이고,
노트북 설정으로 우회할 수 없습니다. `python scripts/init_db.py` 도 같은 이유로 타임아웃납니다.

### ④ URL만 등록해 두기 — 애초에 동작할 수 없었음

한동안 콘솔에 "노션 문서 추가" 폼이 있었습니다. URL과 이름을 넣어 `policy_sources` 에 행을
만드는 기능입니다.

**막힌 이유**: ①이 없으므로 **그 URL을 가져올 수단이 존재하지 않습니다.** 등록은 되지만
`body` 가 영원히 비어 있는 행이 생길 뿐입니다. 운영에서 실제로 그 상태였습니다 —
`B2B 리드 대응 정책` 이 등록돼 있고 `마지막 동기화 —`, 그동안 초안은 톤 규칙 두 개만 보고
작성되고 있었습니다. 그래서 폼을 제거했습니다.

## 3. 그래서 택한 것

**노션 Export zip 을 콘솔에 드롭한다.** 각 구간이 실제로 열려 있는 경로만 씁니다.

```
노션 ──(브라우저: ··· → Export → Markdown & CSV)──▶ zip
     ──(HTTPS 업로드, 443)──▶ 서버 ──▶ DB ──▶ 초안
```

- 노션 API 토큰 불필요, 쿠키 불필요, 로컬 DB 접근 불필요
- 노션 페이지를 볼 수 있는 사람이면 누구나 할 수 있음
- **공식 기능**이므로 노션 내부가 바뀌어도 계속 동작

**올린 파일이 곧 목록입니다.** zip 안의 문서는 전부 반영되고, 처음 보는 문서는
`문의별 참고` 로 자동 등록됩니다 (`policy_sync.register_export_pages`). URL을 손으로 넣는
단계가 없어야 하는 이유는 ④에서 실제로 확인했습니다 — 노션에서 문서를 만드는 사람과 콘솔에
등록하는 사람이 같아야 하고, 한쪽만 하면 조용히 누락됩니다.

**삭제는 하지 않습니다.** zip에 없다고 사라진 것으로 볼 수 없습니다 — 한 페이지만 내보낸
zip일 수도 있고, 그러면 부분 업로드 한 번에 등록부가 비어 버립니다.

### 부수적으로 남긴 경로

`scripts/sync_notion_local.py --server <URL>` — 담당자 PC가 노션을 읽어 **서버 HTTPS로**
올립니다. DB에 직접 쓰지 않으므로 ③의 문제를 피합니다. ②의 쿠키가 동작하는 환경에서는
드롭보다 편합니다(더블클릭 한 번). 서버 인증은 `INTERNAL_API_TOKEN`.

`src/api/policy_api.py` 가 그 상대편입니다. 로컬이 먼저 `GET /api/policy/sources` 로 무엇을
읽어야 하는지 묻고, 읽은 본문을 `POST /api/policy/push` 로 돌려줍니다.

## 4. 설계에서 지킨 것

**저장 로직은 하나뿐입니다.** zip 드롭이든 로컬 푸시든 ①이 부활하든, 전부
`sync_policy_sources(fetcher=…)` 를 통과합니다. `fetcher` 만 바뀝니다. 두 경로가 각자
저장하면 "무엇이 최신인가" 의 답이 경로마다 달라집니다.

**등록부는 서버가 소유합니다.** 올리는 쪽은 본문만 건넵니다. 어떤 행이 갱신될지는 서버의
`policy_sources` 가 정하므로, 등록되지 않은 페이지를 밀어 넣어도 아무 일도 일어나지 않습니다.

**새 문서는 `문의별 참고` 로만.** `항상 적용` 은 모든 회신에 붙어 다니므로 자동으로 늘어나면
안 됩니다. 무엇이 거기 들어갈지는 사람이 콘솔에서 정합니다.

**zip은 저장하지 않습니다.** 메모리에서 읽고 버립니다 — 정책 사본은 이미 DB에 있고, 업로드
파일을 남기면 지워야 할 사본이 하나 더 생깁니다.

## 5. 다시 검토할 때 — 먼저 이것부터 확인

바꾸기 전에 아래를 실제로 돌려 보세요. **조건이 바뀌었다면 더 단순한 쪽으로 돌아가는 것이
맞습니다.** 이 설계는 제약의 결과이지 취향이 아닙니다.

```powershell
# ① 노션 통합 토큰을 받을 수 있게 되었는가?  (가장 중요)
#    https://app.notion.com/developers/connections 에서 만들 수 있는지,
#    그리고 대상 페이지에 Connections 로 연결할 수 있는지.
#    가능하다면: NOTION_TOKEN 을 Render 환경변수에 넣기만 하면 됩니다.
#    sync_policy_sources(fetcher=None) 이 알아서 그 경로를 씁니다 — 코드 변경 없음.

# ③ 사내망이 DB 포트를 열었는가?
Test-NetConnection aws-1-ap-northeast-1.pooler.supabase.com -Port 5432
#    열렸다면 scripts/sync_notion_local.py --local-db 가 다시 동작합니다.

# ② 쿠키 경로가 살아났는가?
.\.venv\Scripts\python.exe scripts\sync_notion_local.py --check
#    "내보내기 파일을 받지 못했습니다" 가 나오면 여전히 file_token 이 필요합니다.
```

**①이 열리면 이 문서의 대부분이 불필요해집니다.** 그때는 zip 드롭을 남겨 두되(오프라인
대비) 콘솔의 `동기화` 버튼이 주된 방법이 됩니다.

## 6. 관련 파일
