# 조사 요청 — 로컬에 있는 데이터를 웹 화면에서 보는 가장 안정적인 방법

> 이 문서 하나만 읽고 조사할 수 있게 상황을 전부 담았다. 저장소를 안 봐도 된다.
> **구현을 요청하는 것이 아니라, 방식의 선택과 그 근거를 검증받으려는 것이다.**

---

## 1. 상황

회사에 **제품 운영 DB 의 일별 스냅샷**이 있다.

- 매일 05:00(KST) 자동화가 운영 MySQL 을 **테이블별 CSV** 로 뽑아 **회사 비공개 GitHub
  저장소**에 커밋한다. (변경분만, 하루 한 커밋)
- 크기: 작업본 CSV 48개 약 **470MB**, `.git` 포함 clone 이 약 **1GB**. 매일 커밋되므로 계속 커진다.
- 내용: 사용자·스페이스·구독·결제·크레딧·프로젝트 등. **이메일·이름·연락처·결제키 같은
  PII 컬럼은 추출 단계에서 아예 제외**돼 있다(마스킹이 아니라 SELECT 에서 뺌). 다만
  프로젝트 제목·파일명 같은 사용자 입력 텍스트는 남아 있어 **사내 전용**이다.
- 이 데이터는 **읽기만 한다.** 수정하지 않는다.

우리는 별도로 **영업 콘솔**(FastAPI + React)을 운영 중인데, **사내망이 아니라 외부 PaaS
(Render)에 HTTPS 로 배포**돼 있다. 사내망 자원을 쓰지 않는다.

**그리고 이 프로젝트에서 사내망 자원을 쓸 수 없다** — 사내 서버를 한 대 받아 띄우는 것,
사내 파일 공유에 배포물을 두는 것, 사내 DNS 를 쓰는 것 전부 못 한다. 배포와 실행은
**개인 PC 와 공개 인터넷만**으로 성립해야 한다.

참고로 이 회사 망은 중앙 관리된다 — 모든 HTTPS 가 어플라이언스에 재서명되고
(`ePrism SSL`), 일부 포트(예: Postgres 5432/6543)의 아웃바운드가 막혀 있다.
HTTPS 443 아웃바운드는 열려 있다.

## 2. 하고 싶은 것

그 스냅샷을 분석해서 지표를 보고 싶다. **단, 데이터가 우리 콘솔 서버나 DB 로 올라가면 안 된다.**

구체적으로:

1. 각자 PC 에 그 git 저장소를 clone 해 둔다.
2. 실행 파일 하나를 그 폴더 옆에 둔다.
3. 실행하면 **하루 한 번 `git pull`** 을 받는다. (실패하면 어쩔 수 없이 이전 데이터로 본다)
4. **계산은 전부 그 PC 에서** 한다.
5. 계산된 **집계값만** 화면에 보여 준다. 원본 행은 그 PC 를 안 떠난다.
6. 웹 화면에서 본다.

## 3. 제약 (양보 불가)

| # | 제약 |
|---|---|
| C1 | **원본 데이터가 사용자 PC 를 안 떠난다.** 우리 콘솔 서버·DB 는 이 데이터를 한 바이트도 받지 않는다 |
| C2 | **집계값도 서버에 저장하지 않는다.** 각자 자기 PC 의 숫자를 본다 (팀이 같은 숫자를 볼 필요 없음) |
| C3 | **여러 명이 쓴다.** 한 사람 PC 에서만 되는 설정은 못 쓴다 |
| C4 | 브라우저를 특정 제품으로 강제하고 싶지 않다 (**Safari 포함**해서 다 되면 좋겠다) |
| C5 | 사용자에게 복잡한 설치·설정을 요구하지 않는다 |
| C6 | 읽기 전용. 되돌려 쓰는 경로가 없다 |
| **C7** | **사내망 자원을 쓸 수 없다.** 사내 서버·사내 파일 공유·사내 DNS 전부 불가. 개인 PC + 공개 인터넷(HTTPS 443)만으로 성립해야 한다 |

**아직 안 정한 것**: 어떤 지표를 볼지. (그건 나중에 정한다 — 지금 조사 대상이 아니다)

## 4. 우리가 이미 확인한 사실 (검증해 주면 좋겠다)

브라우저에서 로컬에 접근하는 길은 셋이고, 각각 벽이 다르다.

### 4-1. 웹 페이지가 로컬 **파일**을 직접 읽기 — `showDirectoryPicker()`

- Chrome/Edge/Opera 만 지원. **Safari·Firefox 미지원.**
- 그리고 웹 페이지는 `git pull` 을 할 수 없다 → 요구 3번을 못 채운다.
- <https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker>

### 4-2. HTTPS 웹 페이지가 로컬 **서버**를 부르기 — `https://우리사이트` → `http://127.0.0.1:PORT`

- **Chrome 142 부터 Local Network Access 권한 프롬프트**가 뜬다(루프백 포함). 허용은
  출처별로 **영구 저장**된다. 거부되면 오류가 CORS 처럼 보이지만 **요청이 서버에 닿지도
  않아 서버 헤더로는 못 고친다.**
  <https://developer.chrome.com/blog/local-network-access>,
  <https://www.dynamsoft.com/web-twain/docs/faq/chromium-142-local-network-access-issue.html>
- 기업 정책 `LocalNetworkAccessAllowedForUrls` 로 프롬프트를 없앨 수 있다.
- **Safari 는 mixed-content `http://localhost` 를 막는 유일한 브라우저**이고 프롬프트조차 없다.
  <https://developer.mozilla.org/en-US/docs/Web/Security/Mixed_content>,
  <https://developer.apple.com/forums/thread/811690>

### 4-3. 로컬 서버가 **자기 페이지를 자기가** 띄우기 — 브라우저가 `http://127.0.0.1:PORT` 를 연다

- 페이지 출처 자체가 루프백 → mixed content 없음, LNA 프롬프트 없음(같은 주소 공간), CORS 없음.
- **모든 브라우저에서 된다(Safari 포함).**
- Jupyter · Grafana · pgAdmin · Docker Desktop · Ollama · DuckDB UI 가 전부 쓰는 패턴.

### 4-4. 배포

- **macOS**: 서명·공증 안 된 바이너리는 Gatekeeper 가 막고, **Sequoia 부터 우클릭 우회가
  없어졌다**(시스템 설정 → 개인정보 보호 및 보안 → 「그래도 열기」 + 관리자 암호).
  단, **격리 속성 `com.apple.quarantine` 은 브라우저가 붙이는 것**이라 `curl`·`scp` 로 받으면
  안 붙는다 → 터미널 한 줄 설치는 Gatekeeper 를 안 건드린다.
- **Windows**: 서명 없으면 SmartScreen 경고(막히지는 않음).
- 웹 페이지에서 로컬 앱을 실행하는 방법은 **커스텀 URL 스킴**(`myapp://`) 하나뿐이고,
  **설치 여부를 안정적으로 감지할 수 없다.**

### 4-5. 계산 엔진

- **DuckDB** CLI 는 의존성 없는 단일 바이너리이고, `read_csv_auto` 로 CSV 를 그 자리에서 읽는다.
- `duckdb -ui` 가 이미 **로컬 HTTP 서버 + SQL 노트북 UI**(기본 `localhost:4213`)를 띄우고
  브라우저를 연다.

## 5. 우리가 잠정적으로 고른 답

**4-3 을 기본으로 한다** — 로컬 에이전트(단일 바이너리)가 pull 하고, DuckDB 로 계산하고,
**자기가 UI 를 `127.0.0.1` 에 띄우고**, 브라우저를 연다.
우리 콘솔의 역할은 ① 내려받기 ② 사용법 ③ `myapp://open` 링크로 줄어든다.

**이유**: 4-2(공개 사이트 → localhost)는 브라우저들이 **지금 조이고 있는 중**이다.
Safari 는 이미 막았고 Chrome 은 2025→2026 에 권한을 새로 넣었다. 그 위에 지으면 다음
변경에 화면이 죽는다. 반면 4-3 은 로컬 개발 생태계 전체가 의존하는 패턴이라 막힐 수 없다.

보안 설계(잠정):
- `127.0.0.1` 에만 바인딩 (`0.0.0.0` 금지)
- **콘솔/화면이 SQL 을 보내지 못한다.** 이름 있는 지표만 부르고, 무엇이 나갈지는 에이전트가 정한다
- 응답에 행이 없다 — 상한(행 수)과 식별자성 컬럼 검사로 **기계가 막는다**
- 그룹 관측치가 N 미만이면 합치거나 뺀다 (집계가 사실상 행이 되는 것 방지)
- 프로세스마다 새로 만드는 베어러 토큰 (localhost 는 같은 PC 의 아무 프로그램이나 두드릴 수 있다)

## 6. 물어보고 싶은 것

1. **4-3 이 정말 가장 안정적인 선택인가?** 우리가 못 본 더 나은 방식이 있나?
   (브라우저 확장, PWA, WebTransport, 로컬 프록시, 그 밖에)

2. **4-1·4-2·4-4 의 사실 관계가 지금도 맞나?** 특히
   - Chrome LNA 의 현재 시행 상태와 `targetAddressSpace` 의 정확한 값
   - Safari 가 `http://localhost` 를 막는 것에 예외나 우회가 생겼는지
   - macOS 최신 버전에서 서명 없는 바이너리·스크립트의 실제 동작
   - `curl` 로 받은 파일에 격리 속성이 안 붙는다는 것이 지금도 맞는지

3. **C7(사내망 자원 불가) 때문에 「공용 서버 한 대가 pull 해서 LAN 에 띄우는」 방식은
   후보가 아니다.** 그걸 권하지 말아 달라. 대신 묻고 싶은 것은 —
   **개인 PC + 공개 인터넷만으로 성립하는 다른 모양**이 또 있나?
   (예: 중앙 관리 망에서 TLS 인터셉션·egress 필터를 지나 `git pull` 과 첫 실행 다운로드를
   안정적으로 하는 방법, 배포물을 공개 인터넷에 두면서 사내 정책을 안 건드리는 방법)

4. **1GB 이고 매일 커지는 git 저장소**를 여러 명이 매일 pull 하는 것이 지속 가능한가?
   (`--filter=blob:none`, shallow clone, 주기적 재-clone 등 무엇이 맞나)

5. **비공개 GitHub 저장소를 여러 사람이 자동 pull** 할 때의 인증 방식으로 무엇이 맞나?
   (에이전트에 토큰을 넣는 것은 배포되므로 불가. `gh auth`·Git Credential Manager·SSH·
   deploy key·GitHub App 중 무엇이 팀 규모에서 관리 가능한가)

6. **단일 바이너리를 Windows·macOS(arm64/amd64) 로 한 대에서 만드는** 가장 현실적인 방법은?
   (Go 는 CGO 없이 크로스 컴파일되지만 DuckDB 임베드는 CGO 가 필요해서, 우리는 DuckDB CLI 를
   별도 프로세스로 호출할 생각이다. 더 나은 방법이 있나)

7. **집계만 나가게 하는 것을 코드로 보장하는** 방법으로 우리 설계(지표 화이트리스트 + 행 수
   상한 + 식별자 컬럼 검사 + 최소 그룹 크기)가 충분한가? 빠진 공격면이 있나?

## 7. 답변에 바라는 형태

- **추론이 아니라 출처와 함께.** 브라우저·OS 정책은 최근 2년 사이에 여러 번 바뀌었다.
- 「된다/안 된다」가 아니라 **「무엇이 언제 깨지는가」**. 우리는 1년 뒤에도 도는 것을 원한다.
- 우리 잠정안이 틀렸으면 **어디가 왜 틀렸는지** 짚어 달라.
