# 왜 정책 문서를 콘솔에 직접 붙여넣는가

> **읽는 이에게.** 이 파일은 "노션 API 쓰면 되는데 왜 안 했지?" 와 "Export zip 받아서
> 올리면 되는데 왜 안 했지?" 라는 두 질문에 답하기 위해 있습니다. 둘 다 합리적이고, 답은
> 각각 "그 API를 쓸 수 없어서" 와 "그 zip이 문서를 안 실어 와서" 입니다. 아래는 실제로
> 시도한 것과 각각이 어디서 막혔는지의 기록입니다. **고치기 전에 §5의 확인 절차부터 돌려
> 보세요** — 조건이 바뀌었다면 더 단순한 방법으로 돌아가는 것이 맞습니다.
>
> 최종 확인: 2026-08-05

---

## 1. 한 줄 요약

노션에서 이 워크스페이스의 정책 문서를 **자동으로 가져올 방법이 없습니다.** 공식 API는 토큰을
못 만들고, 브라우저 쿠키 경로는 파일 다운로드에서 막히고, 공식 Export는 정작 필요한 문서들을
담아 오지 않습니다. 그래서 사람이 본문을 콘솔에 붙여넣습니다.

```
             노션 읽기    DB 쓰기
서버            ✗           ✓        ← 통합 토큰 발급 불가
담당자 PC       ✓           ✗        ← 사내망이 5432/6543 차단
```

그리고 그 둘을 이어 보려던 다리(Export zip)가 §2⑤에서 무너졌습니다.

---

## 2. 시도한 것과 막힌 지점

### ① 노션 공식 API (`NOTION_TOKEN`) — 가장 단순하고, 쓸 수 없음

정상이라면 이게 답입니다. 서버가 통합 토큰으로 페이지를 직접 읽고, 콘솔의 `동기화` 버튼만
있으면 됩니다.

**막힌 이유**: 회사(ESTsoft) 노션 워크스페이스에서 내부 통합(internal integration)을 만들
권한이 없습니다. 토큰을 발급받을 수 없으므로 `NOTION_TOKEN` 이 영원히 비어 있습니다.

이 경로의 코드(`src/integrations/notion.py`, `sync_policy_sources`)도 **지웠습니다.** 한동안
"토큰이 생기면 환경변수만 넣으면 되도록" 남겨 뒀는데, 쓸 수 없는 코드가 남아 있으면 읽는
사람이 "동기화가 되는 모양이네" 로 오해합니다 — 실제로 `policy_sources` 에는 `notion_url`,
`last_synced_at`, `last_error` 열이 답할 수 없는 질문으로 남아 있었습니다(0050 에서 삭제).
되살리려면 커밋 `aa0fc9b` 이전을 보면 되고, 그 전에 아래를 먼저 확인하세요.

> **이 조건만 풀리면 나머지는 전부 필요 없습니다.** §5 참고.

### ② 브라우저 쿠키 (`NOTION_TOKEN_V2`) — 절반만 되고, 지금은 삭제됨

담당자 PC에서 본인 노션 세션 쿠키로 비공개 v3 API(`enqueueTask` → `getTasks`)를 호출해
내보내기를 만들고, 노션이 주는 서명된 URL에서 zip을 받는 방식이었습니다.

**막힌 이유**: 실행 결과입니다.

```
1. enqueueTask (www.notion.so)      →  성공, 서명된 exportURL 반환
2. GET exportURL (file.notion.com)  →  403
   "Access denied! Please ask the owner to share the page with you,
    and log into your account."
```

내보내기 **생성이 성공했다는 것**이 핵심이었습니다 — 쿠키는 유효하고 계정은 그 페이지를 읽을
수 있었습니다. 노션이 파일 호스트를 `file.notion.com` 으로 분리하면서 그쪽은 **별도 쿠키
(`file_token`)** 를 봅니다. 한 작업의 두 단계가 서로 다른 쿠키를 요구합니다.

`NOTION_FILE_TOKEN` 을 지원하도록 고쳐 두었었지만, **⑤ 때문에 성공해도 소용이 없어서**
경로 자체를 지웠습니다 — 받아 오는 것이 부모 페이지 하나뿐이니까요. 코드는 커밋 이력에
있습니다(`src/integrations/notion_session.py`).

### ③ 로컬 스크립트가 DB에 직접 쓰기 — 네트워크가 막음

`scripts/sync_notion_local.py` 의 원래 설계였습니다. 담당자 PC가 노션을 읽고 그 자리에서
`policy_sources` 에 씁니다.

**막힌 이유**: 사내망이 DB 포트를 막습니다. 실측:

```
aws-1-ap-northeast-1.pooler.supabase.com
  5432 : 차단/타임아웃      ← PostgreSQL
  6543 : 차단/타임아웃      ← Supabase 트랜잭션 풀러
   443 : 열림
```

같은 호스트인데 443만 열립니다. DNS도 라우팅도 아닌 **포트 기반 아웃바운드 규칙**이고,
노트북 설정으로 우회할 수 없습니다.

### ④ URL만 등록해 두기 — 애초에 동작할 수 없었음

한동안 콘솔에 "노션 문서 추가" 폼이 있었습니다. URL과 이름을 넣어 `policy_sources` 에 행을
만드는 기능입니다.

**막힌 이유**: ①이 없으므로 **그 URL을 가져올 수단이 존재하지 않습니다.** 등록은 되지만
`body` 가 영원히 비어 있는 행이 생길 뿐입니다. 운영에서 실제로 그 상태였습니다 —
`B2B 리드 대응 정책` 이 등록돼 있고 `마지막 동기화 —`, 그동안 초안은 톤 규칙 두 개만 보고
작성되고 있었습니다.

### ⑤ 노션 Export zip 드롭 — **문서를 안 실어 옵니다** (2026-08-05)

한동안 이것이 주된 경로였습니다. 노션 `··· → Export → Markdown & CSV` 로 받은 zip을 콘솔에
드롭하면 서버가 파싱해 저장하고, 처음 보는 문서는 자동 등록까지 했습니다. 공식 기능이고,
토큰도 쿠키도 DB 접근도 필요 없었습니다.

**막힌 이유**: 실제로 받은 파일을 열어 봤습니다.

```
Export.zip
└── ExportBlock-1c620bee-...-Part-1.zip        ← zip 안에 zip
    └── Private & Shared/
        └── B2B 리드 대응 정책 3a2f11f6....md   ← 이것 하나가 전부 (6,179 bytes)
```

두 가지가 동시에 드러났습니다.

**(가) 필요한 문서가 하나도 안 들어옵니다.** 정책 페이지가 가리키는 문서 — CS 문의 대응
가이드, Business 플랜 홍보, 견적 및 맞춤형 플랜 안내, 지원하는 언어, B2B 플랜 비교표,
크레딧 차감 정책, 기본 메일 템플릿 ENG/KR — 은 전부 표 안의 **링크**로만 남습니다:

```markdown
| 견적·가격 문의 | ... | [견적 및 맞춤형 플랜 안내](https://app.notion.com/p/3b1f11f6...) |
```

노션 Export의 `Include subpages` 는 그 페이지의 **자손(descendant)** 만 내보냅니다. 이
문서들은 자식이 아니라 워크스페이스 다른 곳에 있는 별개 페이지를 링크로 가리키는 구조라,
옵션을 켜도 따라오지 않습니다. 링크가 상대경로가 아니라 `app.notion.com` 절대주소로 찍혀
있는 것이 그 증거입니다 — 내보내기에 포함된 페이지는 상대경로로 적힙니다.

**(나) 파서가 이 파일을 아예 거절합니다.** 노션이 내보내기를 `Part-1` 로 나눠 zip 안에 zip을
넣어 주는데, `read_export` 는 바깥 zip의 멤버만 보고 `.md` 를 못 찾아
`"내보내기에서 노션 페이지(.md)를 찾지 못했습니다"` 로 400을 냅니다. 즉 **정상적인 노션
내보내기를 올려도 실패합니다.**

(나)는 몇 줄이면 고칩니다. (가)는 못 고칩니다 — 노션이 안 주는 것을 파서가 만들어 낼 수는
없습니다. 그리고 (가) 때문에, zip 경로가 "성공했습니다" 라고 답하면서 정책 문서 한 장만
넣고 나머지 여덟 개를 조용히 빠뜨리는 것이 **정상 동작**이 됩니다. ④에서 지우기로 했던
바로 그 실패 방식입니다.

## 3. 그래서 택한 것

**콘솔에 제목과 본문을 붙여넣습니다.** `이메일 템플릿 → 정책 문서 → 직접 추가`.

```
노션 ──(사람이 복사)──▶ 콘솔 붙여넣기 ──▶ DB ──▶ 초안
```

- 노션 API 토큰 불필요, 쿠키 불필요, 로컬 DB 접근 불필요, 파일 불필요
- **본문이 같이 들어옵니다.** ④와 ⑤가 실패한 지점이 정확히 이것이었습니다 — 등록은 되는데
  내용이 안 오는 것. 붙여넣기는 등록과 내용이 한 동작입니다.
- 화면에 보이는 것이 초안이 읽는 것입니다. 사본이 어긋날 구간이 없습니다.
- 표는 노션에서 복사하면 탭 구분 텍스트로 붙고, 모델은 그대로 읽습니다.

**어떤 문서든 고칠 수 있습니다.** `수정` 버튼. 자동으로 덮어쓰는 경로가 더는 없으므로,
여기서 고친 것은 여기서 고칠 때까지 그대로입니다.

**대가**: 문서 하나에 붙여넣기 한 번. 여덟 개면 여덟 번입니다. zip 한 번으로 끝나던 것과
비교되지만, 그 한 번이 실어 오던 것이 한 개였습니다.

## 4. 설계에서 지킨 것

**이 콘솔이 원본입니다.** 위쪽에 아무것도 없습니다. 그래서 "무엇이 최신인가" 라는 질문이
아예 성립하지 않고, 여기서 고친 것을 뒤에서 되돌려 놓는 것도 없습니다. 0050 이
`notion_url` · `last_synced_at` · `last_error` 를 지운 이유가 그것입니다 — 답할 수 없는
질문을 스키마에 남겨 두면 다음 사람이 그 답을 찾으러 갑니다.

**본문 없는 등록은 만들 수 없습니다.** ④와 ⑤가 남긴 교훈이고, 지금은 구조적으로 불가능합니다 —
문서를 만드는 화면이 본문을 같이 받습니다.

**콘솔 편집은 초안이 읽는 사본까지 즉시 밀어 넣습니다**(`refresh_knowledge_copy`). 안 그러면
화면에는 새 내용이 보이는데 회신은 옛 내용으로 나가고, 그건 눈치챌 방법이 없습니다.

**어떤 문의에 어떤 문서를 쓸지는 코드에 없습니다.** 모델이 문서 목록(제목·요약)을 보고
고릅니다(`llm/knowledge.py`). 정책도 문서 이름도 바뀌므로, 매핑을 굳히면 바뀔 때마다 아무
흔적 없이 끊깁니다.

## 5. 다시 검토할 때 — 먼저 이것부터 확인

바꾸기 전에 아래를 실제로 돌려 보세요. **조건이 바뀌었다면 더 단순한 쪽으로 돌아가는 것이
맞습니다.** 이 설계는 제약의 결과이지 취향이 아닙니다.

```powershell
# ① 노션 통합 토큰을 받을 수 있게 되었는가?  (가장 중요)
#    https://app.notion.com/developers/connections 에서 만들 수 있는지,
#    그리고 대상 페이지에 Connections 로 연결할 수 있는지.
#    가능하다면: 커밋 aa0fc9b 이전의 src/integrations/notion.py + sync_policy_sources 를
#    되살리고, policy_sources 에 notion_url / last_synced_at / last_error 를 다시 추가.
#    그때도 붙여넣은 문서는 notion_url 이 비어 있으니 건너뛰게 두면 됩니다.

# ⑤ Export 가 실제로 무엇을 담는지 다시 세어 보기
#    정책 페이지에서 ··· → Export → Markdown & CSV, Include subpages 켜고 받은 뒤:
.\.venv\Scripts\python.exe -c "import zipfile,sys; z=zipfile.ZipFile(sys.argv[1]); print(*z.namelist(),sep=chr(10))" "$HOME\Downloads\Export.zip"
#    .md 가 여러 개면 구조가 바뀐 것입니다 (문서들을 정책 페이지 아래로 옮겼다는 뜻).
#    그때는 zip 경로를 되살릴 가치가 있고, zip-안에-zip 언랩만 추가하면 됩니다.

# ③ 사내망이 DB 포트를 열었는가?
Test-NetConnection aws-1-ap-northeast-1.pooler.supabase.com -Port 5432
```

**①이 열리면 이 문서의 대부분이 불필요해집니다.** 그때는 붙여넣기를 남겨 두되(오프라인 대비)
콘솔의 `동기화` 가 주된 방법이 됩니다.
