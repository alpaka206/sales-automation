# ADR: 실측 실패에 따른 답변 요소 조합과 제한된 근거 검사

상태: 로컬 구현, 실제 Vertex 개발셋 평가 완료 여부와 수치는 [평가 결과](../policy-response/runs/2026-09-21-live/results.md)에 기록한다. 운영 배포·발송 승인 아님.

## Context / 관측한 문제

첫 로컬 개선 후 Gemini 2.5 Flash/Pro를 실제 호출했다. 동일 합성 정책·14개 문의·2반복에서 라우터/허용 문서 전체 분기를 비교했다. 가상 회사 정책이며 실제 회사 정책의 정확도 시험은 아니다. 원문에 없는 환불 처리 5~10일, 실행하지 않은 환불 접수·진행 상태, 존재가 확인되지 않은 화면 메뉴가 생성됐다. 원문 전체 주입도 이를 해결하지 못했다.

후속 소규모 시험에서는 정책 인용을 추가해도 오류가 남았고, Pro 추론 한도를 128→1024로 늘려도 충분한 개선을 보이지 않았다. 질문별 답변 요소를 생성한 뒤 별도 body를 다시 쓰게 했을 때에는 **요소에 있던 조건이 body에서 빠지는 사례**를 직접 관측했다. S02는 “아니요”를 직전 다운로드 질문의 답으로 이해했어도 원래 환불 문의를 끝까지 답하지 않았다.

## Decision / 실제 구현

- 정상 경로의 생성 호출은 하나다. `GroundedDraftResult`는 정확한 원문 인용과 질문별 `AnswerPoint` 목록을 받는다. `supported_answer`와 `verification_needed`는 고객 언어의 완성 문장이다. `compose_answer`가 순서대로 연결한다. 별도 body 재서술을 제거해 이미 생성한 답변의 누락 경로를 줄인다. 질문 식별/문장 의미의 정확성을 보장하지는 않는다.
- 후속 답변 입력 지시는 최신 짧은 응답을 직전 질문과 원래 미해결 문의에 연결한다. “이미 설명한 것 생략”이 미설명 조건까지 없애지 않도록 범위를 명시했다. 리마인더 생성 경로는 그대로다.
- `PolicyQuote`는 생성에 실제 제공한 source_id와 원문 내 연속 구절인지 검사한다. 규칙과 지식 문서에 ID/version 표시를 추가한다. 인용 유효성과 답변의 논리적 타당성은 다르다.
- `check_draft`는 입력 원문/고객 발화에 없는 숫자 기간과 일부 명백한 실행 상태 표현을 감지한다. 실패하면 같은 snapshot으로 **의미 검사 재작성 1회**만 허용한다. 재실패는 초안 오류이며 고객에 대한 자동 거절이 아니다. 기존 JSON 형식 재시도/통신 재시도까지 전체 API 호출이 2회라는 뜻은 아니다.
- 실제 실행 근거가 없으므로 “아직 완료되지 않았다”도 확인된 상태로 취급하지 않는다. 주 비교 뒤 관측된 이 문장 계열을 추가 검사했다. durable inbound job은 `DraftEvidenceError`를 terminal로 처리해 이미 소진한 의미 재작성을 큐에서 8회 반복하지 않는다.
- 언어·링크·기존 가격 처리 뒤에도 본문을 검사한다. Event에는 검사 상태/생성 횟수/인용 ID/답변 요소 개수만 추가한다. `semantic_validation=NOT_RUN`, `delivery_permission=DRAFT_ONLY`를 유지한다.
- 기본 모델·추론 한도 128·리마인더·운영 설정은 유지한다. 명시적 호출별 thinking budget은 평가 adapter의 비교용으로만 사용했다. 새 DB 테이블, migration, 인덱스, 그래프, 별도 검증 모델은 없다.

## Alternatives / 반박

| 대안 | 관측/반론 | 선택 |
|---|---|---|
| 인용을 붙인 자유 본문만 생성 | 원문 인용이 맞아도 허위 상태/무응답이 남음 | 인용만을 검증 완료로 삼지 않음 |
| 답변 요소 + 자유 본문 중복 출력 | 같은 호출 안에서도 본문에서 조건 누락 관측 | 본문을 코드에서 조합 |
| Pro 추론 한도 상시 확대 | 6개 탐색 실행에서 누락/허위 상태가 남고 지연 증가; 독립 통제 실험 아님 | 기본값 유지 |
| 모든 원문 상시 주입 | 개발셋에서도 같은 오류 발생; 실제 정책 크기는 확보 못함 | 기존 라우터 유지, 일반 우열 결론 보류 |
| 검사 실패 때 문장을 삭제하거나 거절 답변 생성 | 필요한 정보까지 지우거나 정책 판단을 바꿀 위험 | 제한 재작성 뒤 검토 가능한 오류 |
| 정규식으로 정책 전체 판정 | 인용 의미/조건·예외 범위/동의어·부정 범위를 증명 못함 | 제한 검사만, 의미 인증 금지 |

## Evidence / 테스트

실제 출력·판정·토큰·지연·탐색 실패는 [live 결과](../policy-response/runs/2026-09-21-live/results.md), 원본 가상 정책은 `tests/fixtures/policy_response_live.json`에 있다. fixture의 기대사항은 첫 호출 전에 작성했으나 구현자는 전체 개발셋을 보았으므로 holdout이 아니다. 단일 구현 에이전트의 비맹검 판정이며 독립 전문가 확인은 NOT_RUN이다.

`tests/test_draft_evidence.py`는 관측한 기간/상태 오류, 원문 인용 위조, 번역 기간 단위, 부정 문장, 답변 요소 유지와 schema를 검증한다. `test_policy_context.py::test_unsupported_duration_gets_one_repair_then_is_kept_out_of_pending`는 실제 경로의 1회 재작성과 재실패 시 pending 차단을 검증한다. `test_llm_client.py::test_explicit_draft_thinking_budget_survives_schema_retry`는 비교 설정 전달을 확인한다.

`test_inbound_worker.py::test_exhausted_evidence_repair_is_not_sampled_again_by_the_queue`는 durable queue가 재실패 초안을 자동 반복 생성하지 않는지 확인한다. 주 비교 56개 이후 추가한 부정 상태 검사/큐 변경은 최신 전체 로컬 시험으로 검증했고, 실제 모델은 S14 2개만 최종 재확인했다. 전체 56개를 최종 코드에서 재평가했다고 주장하지 않는다.

## Trade-offs / Risks / 재검토 조건

재작성은 토큰·지연과 초안 실패율을 늘린다. 차단된 초안도 유효 답변율의 분모에 포함한다. 기간의 숫자가 어느 원문에 있다는 사실만으로 해당 고객에게 적용 가능하다고 볼 수 없다. 고객이 말한 기간은 재서술 가능할 뿐 검증된 사실이 아니다. 문자열 검사는 과잉 차단과 우회 표현을 모두 가질 수 있다. 인용 누락/충분성, 계약 승인 여부, 시행일 의미, UI 절차, 고객 주장 승격은 완전 검증되지 않는다.

답변 요소는 모델이 작성한 결과이지 신뢰 가능한 정책 결정기가 아니다. 생성된 문장을 조합해도 의미 오류는 남는다. 한국어 자연스러움/실제 상담사 수정시간은 정량 측정하지 않았다. 정책 담당자 원문·실제 문의의 독립 평가에서 false positive와 유효 답변율/지연을 함께 측정한 뒤 검사 범위·조건·구조를 재검토한다.

복구는 해당 생성 schema/조합/검사 변경을 함께 되돌리는 코드 변경이다. 기존 Event의 추가 필드는 무시 가능해 DB migration이 필요 없다. 되돌리면 관측된 허위 기간/상태 차단도 사라지므로 운영 책임자의 검토가 필요하다. 이번 작업에서 운영 rollback은 실행하지 않았다.
