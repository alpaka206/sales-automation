## 2. MED — 유지보수성 / 분해 (사용자가 물어본 두 파일 포함)

- **`agents/send_worker.py:_send_one` (~100줄)** — send 재시도/상태전환/티켓이동/engagement로깅/실패처리 혼재 → 분해. + **티켓 단계 이동 로직이 `approval.mark_sent`와 중복**(공유 헬퍼로). + 실패 경로가 claim 재확인 없이 `send_failed`로 덮어씀(멀티워커 위험). + `asyncio.get_event_loop()` deprecated → `time.monotonic()`.
- **`agents/inbound.py:_fetch_contact (~140줄)` / `_persist (~117줄)`** — 본문 4-way 폴백·각종 fetch·enrichment 혼재 → 헬퍼 추출. `_persist`의 대화 조회/생성 블록이 `_existing_pending_draft_id`와 중복("수동 동기화" 위험).
- **`agents/outbound/agent.py:_process_candidate`** — 라우팅·점수·초안·저장·알림 혼재. stats 키 매직스트링(`"drafted"` 등)이 init과 분리 → 오타 시 조용히 새 키.
- **`integrations/hubspot.py`** — async vs `*_sync` 메서드 쌍 **대량 중복**(헤더/클라이언트 생성 ~12회, DTO 매핑 중복). 재시도/백오프가 **일부 async 메서드에만** 연결되고 sync·polling 경로엔 없음 → 레이트리밋에 취약.
- **소스 어댑터** — `discover()`마다 `SourceFilters` 파싱 2줄 6회 중복; 이메일 추출 구현 3종(youtube 자체 regex vs `email_discovery` 공용). → `base.py`/공용 util로.
- **쿼터 파일 로직** youtube/google_search 바이트단위 중복 → `common/quota.py`.
- **세션 관리 혼재** — `SessionLocal()`+try/finally vs `with SessionLocal()` 혼용 → `with`로 표준화(예외 시 롤백 보장).
- **fetch/HTML strip 3중 구현**(web_fetch/email_discovery/ai_browser) — 그리고 **SSRF 가드는 web_fetch에만** 있음 → 공용 fetcher로 통합 + SSRF 하드닝.
