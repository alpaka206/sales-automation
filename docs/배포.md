# 배포

로컬에서는 `scripts\run.bat`으로 실행합니다. HubSpot 웹훅을 받으려면 HTTPS 공개 주소가 필요하므로 Cloudflare Tunnel이나 단일 FastAPI 컨테이너를 사용합니다.

운영에서는 한 프로세스만 백그라운드 폴러와 발송 워커를 실행해야 합니다. 여러 웹 프로세스를 쓸 경우 워커 전용 프로세스를 하나만 두고 나머지에서는 관련 환경변수를 끕니다.

마이그레이션은 배포 방식에 맞춰 자동 실행됩니다. `render.yaml`의 네이티브 Render 배포는
build command에서 `scripts/init_db.py`를 실행하고, Docker 배포는 entrypoint가 기동 전에 같은
스크립트를 실행합니다. 둘 다 실패하면 새 버전이 트래픽을 받지 않습니다. Docker에서만
`MIGRATE_ON_START=false`로 기동 시 실행을 끌 수 있습니다.

배포 전 확인:

1. PostgreSQL `DATABASE_URL` (Render는 빌드 시, Docker는 기동 시 자동 마이그레이션)
2. `PUBLIC_BASE_URL`과 인증 설정
3. HubSpot 웹훅 서명 검증용 secret
4. SMTP 자격증명 확인 및 승인된 초안 한 건의 실발송 확인
5. 실제 HubSpot 단계 ID 확인
6. `/healthz`, `/logs`, `/operations` 확인
7. `/app` 확인 — `/healthz`가 `console: true`면 번들이 있는 것입니다

Render 배포는 `LIVE_EXTERNAL_WRITES=true`로 실발송합니다. 긴급 중단이 필요하면
`LIVE_EXTERNAL_WRITES=false`로 바꾸거나 코드의 `EMAIL_SENDING_ENABLED`를 끕니다. 특정 내부
주소로 수신자를 바꾸는 테스트 모드는 없습니다.

컨테이너는 React 콘솔을 스스로 빌드합니다(Dockerfile의 node 스테이지). 번들은 git에 없으므로
`docker build` 없이 소스만 배포하는 방식이라면 `npm --prefix frontend ci && npm --prefix frontend run build`
를 먼저 돌려야 `/app`이 응답합니다.
