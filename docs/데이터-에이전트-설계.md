# 로컬 데이터 에이전트 — 설계 (2026-09-10)

> 구현 없음. 이 문서는 **무엇을 만들지와 왜 그렇게 만드는지**만 정한다.
> 조사 근거와 다른 대안(A·C·D)의 비교는 `데이터-스냅샷-로컬-분석-설계.md` 에 있다.

## 0. 확정된 것

운영자가 정한 모양:

> 로컬에 그 git 을 받아 두고, 실행 파일을 그 옆에 둔다. 실행하면 pull 을 받고,
> 우리가 정해 둔 포트(예: 1234)에 붙어서, **에이전트가 보내 준 것만** 콘솔이 보여 준다.
> **전체 데이터가 아니라 우리가 필요한 데이터만** 보낸다.
> pull 을 못 받았으면 **어쩔 수 없이 이전 정보를 본다.**

| 요구 | 설계에 어떻게 들어갔나 |
|---|---|
| 원본은 이 PC 를 안 떠난다 | 에이전트가 **집계만** 내보낸다. 행을 내보내는 길이 아예 없다 (§3) |
| 계산은 로컬에서 | DuckDB 가 CSV 를 직접 읽어 계산 (§2-3) |
| 우리 콘솔에서 본다 | 콘솔이 `http://127.0.0.1:<포트>` 를 부른다 (§4) |
| 여러 명이 쓴다 | 각자 자기 PC 에서 자기 clone 을 계산한다. **팀이 같은 숫자를 보지는 않는다** (§9 ①) |
| 읽기만 한다 | `git pull --ff-only`. 되돌려 쓰는 경로 없음 |
| pull 실패해도 계속 | 이전 데이터로 계속하고 **화면이 그렇다고 말한다** (§7) |
| 브라우저 다 풀어놓기 | Chrome·Edge·Firefox 는 콘솔에서, **Safari 는 폴백 화면**에서 (§4-3) |

## 1. 전체 그림

```
 ┌─ 사용자 PC ───────────────────────────────────────────────┐
 │                                                            │
 │   perso-data-snapshot/          ← 그 git clone (읽기 전용)  │
 │     └ data/*.csv                                           │
 │   perso-agent(.exe)             ← 그 옆에 두는 실행 파일     │
 │        │                                                   │
 │        ├ 1. 옆 폴더를 찾는다                                 │
 │        ├ 2. git pull --ff-only  (하루 한 번, 실패해도 계속)   │
 │        ├ 3. DuckDB 로 지표를 계산한다                        │
 │        ├ 4. 127.0.0.1:<포트> 에 HTTP 서버                    │
 │        └ 5. 브라우저로 콘솔을 연다 (짝짓기 URL)               │
 │             │                    ▲                         │
 │             │  집계 JSON 만       │ 이름 있는 지표 요청       │
 │             ▼                    │                         │
 │   [브라우저] ──────────────────────┘                         │
 └──────┬─────────────────────────────────────────────────────┘
        │  HTTPS (우리 콘솔 화면·로그인·우리 데이터)
        ▼
   https://sales-automation-…onrender.com
        └ 화면과 지표 정의를 준다. **스냅샷 데이터는 하나도 안 받는다.**
```

**서버는 이 데이터를 한 바이트도 안 본다.** 브라우저 안에서만 두 출처가 만난다.

## 2. 로컬 에이전트

### 2-1. 하는 일

| # | 무엇 | 실패하면 |
|---|---|---|
| 1 | 자기 옆에서 `perso-data-snapshot/` 을 찾는다 (`data/manifest.json` 이 있는지로 확인) | 「폴더를 못 찾았습니다」 + 예상 경로를 적어 준다. 사용자가 경로를 지정할 수 있다 |
| 2 | 마지막 pull 이 24시간 지났으면 `git pull --ff-only` | **계속 진행한다.** 이전 데이터로 서비스하고 실패 사유를 상태에 남긴다 |
| 3 | DuckDB 를 준비한다 (있으면 쓰고, 없으면 공식 단일 바이너리를 받아 옆에 둔다) | 「DuckDB 를 준비하지 못했습니다」 + 수동 설치 안내. 여기서는 멈춘다 |
| 4 | `127.0.0.1` 의 포트 하나에 HTTP 서버를 연다 | 포트가 다 막혔으면 그 사실을 적고 멈춘다 (§5-3) |
| 5 | 기본 브라우저로 콘솔의 짝짓기 URL 을 연다 | 브라우저를 못 열면 URL 을 콘솔(터미널)에 찍는다 |

**상주하지 않는다.** 실행할 때 돌고, 창을 닫으면 끝난다. 상주는 자동 시작·자동 업데이트·
「꺼져 있는데 켜져 있는 줄 아는」 상태를 전부 끌고 온다.

### 2-2. pull 정책

- **하루 한 번**을 실행 시점에 잰다 — 마지막 성공 시각을 `.perso-agent/state.json` 에 적는다.
- `--ff-only` 다. 읽기만 하므로 충돌이 날 수 없고, 나면 그건 사람이 볼 사고다.
- **실패해도 서비스한다.** 인증 만료·네트워크 없음·저장소 이동 모두 「이전 데이터로 계속」이다.
  대신 §7 대로 화면이 낡았다고 말한다.
- 강제 갱신 버튼을 둔다(24시간을 안 기다림).

> **저장소가 커진다.** 지금 팩 532MB 인데 매일 1GB 어치 CSV 를 커밋한다. 새로 받는 사람은
> `git clone --filter=blob:none --depth 1` 로 시작하는 것이 맞다. 에이전트가 **pull 소요
> 시간과 폴더 크기를 상태에 적어** 두면 언제 손볼지가 보인다.

### 2-3. 계산

- DuckDB 가 `data/*.csv` 를 **그 자리에서** 읽는다(`read_csv_auto`). 복사본을 안 만든다.
- 자주 쓰는 조인은 **뷰**로 둔다 (`views.sql`). `data/manifest.json` 에 FK 가 적혀 있다.
- 무거운 지표는 결과만 로컬 캐시(`.perso-agent/cache.duckdb`)에 두고 pull 이 바뀌었을 때만
  다시 만든다. **캐시 키는 그 pull 의 커밋 sha** 다 — 시간이 아니라.

## 3. 계약 (API) — 이 설계의 심장

### 3-1. 원칙 셋

**① 콘솔은 SQL 을 보내지 않는다. 이름 있는 지표를 부른다.**

```
   ❌  POST /query   { sql: "SELECT * FROM user" }
   ✅  GET  /metrics/plan_mix?from=2026-01&to=2026-09
```

콘솔이 SQL 을 보낼 수 있으면, **콘솔에 닿을 수 있는 누구든** 원본을 그대로 빼낼 수 있다 —
LNA 권한을 받아 낸 악성 페이지도, 같은 PC 의 다른 프로그램도. **무엇이 나갈지는 에이전트가
정한다.** 지표 정의는 에이전트 안에 있고, 콘솔은 이름과 인자만 안다.

「우리가 필요한 데이터만 보낸다」가 정확히 이 뜻이다.

**② 응답에 행이 없다.**

모든 응답은 집계다. 코드로도 막는다 — 지표 실행 결과가

- 미리 정한 상한(예: 5,000행)을 넘거나
- 식별자성 컬럼(`*_seq`, `*_id`, `email`, `uuid`)을 담고 있으면

**응답하지 않고 오류로 끝난다.** 「집계만 보낸다」를 사람이 지키는 규칙이 아니라 기계가
재는 값으로 만든다.

**③ 최소 묶음 크기.** `GROUP BY` 를 잘게 쪼개면 집계가 사실상 행이 된다. 그룹의 관측치가
N(예: 5) 미만이면 그 행을 **`기타` 로 합치거나 빼고**, 뺐다는 사실을 응답에 적는다.

### 3-2. 엔드포인트

| 메서드 | 경로 | 무엇 | 인증 |
|---|---|---|---|
| GET | `/v1/health` | 살아 있나. **토큰 없이** 답한다(콘솔이 「켜져 있나」를 알아야 하므로) — 버전과 포트만 | ✗ |
| GET | `/v1/status` | 데이터 기준 커밋·기준 시각·마지막 pull 시도/결과·폴더 크기·DuckDB 버전 | ✓ |
| GET | `/v1/metrics` | 이 에이전트가 아는 지표 목록과 인자 스키마 | ✓ |
| GET | `/v1/metrics/{name}` | 그 지표의 **집계 결과** | ✓ |
| POST | `/v1/refresh` | 지금 pull 한다 (24시간을 안 기다림) | ✓ |
| POST | `/v1/shutdown` | 에이전트를 끈다 | ✓ |

**버전을 경로에 박는다**(`/v1`). 콘솔은 배포로 바뀌고 에이전트는 사람이 받아야 바뀐다 —
둘의 버전이 어긋나는 순간이 반드시 오고, 그때 조용히 틀린 값을 그리면 안 된다.
`/v1/health` 가 에이전트 버전을 돌려주고 **콘솔이 자기가 아는 버전과 비교해 화면에 적는다.**

### 3-3. 응답 모양

```jsonc
{
  "metric": "plan_mix",
  "params": { "from": "2026-01", "to": "2026-09" },
  "as_of": {                       // 어느 데이터로 계산했나 — 화면이 반드시 적는다
    "commit": "0b87377",
    "committed_at": "2026-09-10T05:00:12Z",
    "pulled_at": "2026-09-10T09:31:02Z",
    "stale": false
  },
  "columns": [ {"name":"plan","type":"text"}, {"name":"users","type":"int"} ],
  "rows": [ ["PRO", 1234], ["Creator", 567] ],   // 집계된 행만
  "suppressed_groups": 3,          // ③ 최소 묶음 때문에 뺀 그룹 수
  "computed_ms": 412
}
```

## 4. 브라우저 — 실제로 어떻게 되나

### 4-1. Chrome / Edge — **권한 한 번**

- Chrome 141(2025-09-30) 예고 → **142 시행**. 공개 출처(HTTPS)가 루프백에 접근하면
  **Local Network Access 권한**을 묻는다.
- **허용은 출처별로 영구 저장된다** — 매 방문마다 묻지 않는다. 우리 콘솔 도메인에 한 번.
- 콘솔의 fetch 에 **`targetAddressSpace`** 를 붙여야 브라우저가 목적지를 안다.
  (스펙에 `local`·`loopback` 이 있고 어느 값을 써야 하는지는 **구현 시 실제 브라우저로
  확인할 것** — 문서마다 표기가 다르다.)
- 거부하면 오류가 **CORS 처럼 보이지만 CORS 가 아니다**: 「Permission was denied for this
  request to access the `unknown` address space」. **요청이 서버에 닿지도 않으므로 서버
  헤더로는 아무것도 못 고친다.** 화면이 이 경우를 CORS 설정 문제로 안내하면 안 된다.

### 4-2. 조직이라면 프롬프트를 없앨 수 있다

Chrome/Edge 정책 **`LocalNetworkAccessAllowedForUrls`** 에 우리 콘솔 도메인을 넣으면 프롬프트가
사라진다. 「여러 명이 쓴다」면 이게 가장 깔끔한 답이다 — 각자 권한을 누르지 않아도 된다.
**IT 에 물어볼 것**(§9 ③).

### 4-3. Safari — 안 된다

Safari 는 **mixed-content `http://localhost` 요청을 막는 유일한 브라우저**이고 **프롬프트도
안 뜬다.** 우회할 방법이 없다(로컬에 HTTPS 인증서를 깔아도 macOS 의 로컬 네트워크 권한이 또
있고, 팀에 CA 를 설치시키는 비용이 더 크다).

### 4-4. 그래서 **같은 에이전트가 문을 두 개 연다**

에이전트는 이미 HTTP 서버와 데이터를 갖고 있다. 화면 하나를 더 서빙하는 비용은 거의 없다.

| | 콘솔에서 (`https://…onrender.com`) | 에이전트에서 (`http://127.0.0.1:<포트>`) |
|---|---|---|
| Chrome · Edge | ✅ 권한 한 번 | ✅ |
| Firefox | ✅ | ✅ |
| **Safari** | ❌ | ✅ |

- 에이전트가 브라우저를 열 때 **Safari 가 기본 브라우저면 자기 화면**을, 아니면 **콘솔**을 연다.
- 콘솔 화면은 붙지 못하면 「이 브라우저에서는 여기서 못 봅니다 → `http://127.0.0.1:<포트>` 로
  가세요」라고 **정확히** 적는다.
- 두 화면은 **같은 지표 API 를 부른다.** 화면 코드가 두 벌이 되면 숫자가 갈린다.

## 5. 포트와 짝짓기

### 5-1. 토큰이 왜 필요한가

`127.0.0.1` 은 **그 PC 의 아무 프로그램이나 두드릴 수 있다.** CORS 는 브라우저만 구속하고
다른 로컬 프로세스는 못 막는다. LNA 권한도 브라우저 쪽 방어다.

→ **베어러 토큰.** 에이전트가 켜질 때마다 새로 만들고(프로세스 수명), `/v1/health` 를 뺀
모든 경로가 요구한다.

### 5-2. 짝짓기 — 사용자가 아무것도 안 친다

```
 1. 에이전트가 켜진다 → 포트 P, 토큰 T 를 만든다
 2. 브라우저를 연다:
      https://<콘솔>/app/data#agent=P&token=T
                              ↑ 프래그먼트라 **서버로 안 간다** (우리 로그에도 안 남는다)
 3. 콘솔 화면이 그 값을 읽어 localStorage 에 저장하고
    즉시 history.replaceState 로 주소창에서 지운다
 4. 이후 콘솔은 저장된 P·T 로 에이전트를 부른다
```

- 토큰이 **URL 프래그먼트**인 것이 요점이다 — 쿼리스트링이면 우리 서버 접근 로그에 남는다.
- 프래그먼트도 **브라우저 히스토리에는 남는다.** 그래서 토큰은 프로세스마다 새로 만들고,
  에이전트가 꺼지면 무효다.
- 에이전트가 다시 켜지면 토큰이 바뀐다 → 콘솔의 저장값이 401 을 받는다 → 화면이
  「에이전트를 다시 연결하세요」로 떨어지고 `persodata://open` 버튼을 준다.

### 5-3. 포트

**고정 1234 는 위험하다** — 다른 프로그램이 쓰고 있으면 그 프로그램에 요청이 간다.

- 후보를 순서대로 시도한다: `43110, 43111, … 43119` (흔히 안 쓰는 대역)
- 실제로 연 포트를 `.perso-agent/state.json` 과 짝짓기 URL 에 싣는다
- **콘솔이 포트를 훑지 않는다.** 여러 포트를 두드리면 LNA 프롬프트가 여러 번 뜨고 느리다.
  콘솔은 **저장된 포트 하나**만 부르고, 실패하면 「에이전트를 실행하세요」로 간다.
- 에이전트는 **`127.0.0.1` 에만** 바인딩한다. `0.0.0.0` 이면 같은 와이파이의 누구나 본다.

## 6. 보안 불변식 (양보 없음)

1. **행은 안 나간다.** 지표 결과가 §3-1 ② 의 검사에 걸리면 응답하지 않는다.
2. **콘솔은 SQL 을 못 보낸다.** 지표 이름과 인자만.
3. **`127.0.0.1` 바인딩.** 옵션으로도 열지 않는다.
4. **CORS 허용 출처는 우리 콘솔 도메인 하나.** `*` 금지. `Access-Control-Allow-Credentials`
   는 쓰지 않는다(토큰은 헤더로 간다 — 쿠키를 안 쓰면 CSRF 표면이 사라진다).
5. **토큰은 프로세스마다 새로.** 파일에 영구 저장하지 않는다.
6. **에이전트는 어디로도 보고하지 않는다.** 텔레메트리·에러 리포트·자동 업데이트 확인 전부 없음.
7. **우리 서버는 이 데이터를 저장하지 않는다.** 지표 값을 받아 DB 에 쓰는 코드가 생기면
   그 순간 「안 나간다」가 깨진다.
8. **`persodata://` 는 인자를 안 받는다.** 「열어라」 하나. 경로를 받으면 그것이 공격면이다.

## 7. 낡았다는 것을 화면이 말한다

이 저장소가 같은 자리에서 여러 번 당했다 — **조용히 낡은 값이 맞는 값처럼 보이는 것**.

콘솔 화면 맨 위에 항상 한 줄:

```
  데이터 기준 2026-09-10 05:00 (커밋 0b87377) · 3시간 전에 받음        [지금 받기]
  ⚠️ 2026-09-08 05:00 기준입니다 — 2일치가 밀렸습니다. 마지막 시도 실패: 인증 만료
```

- **`as_of` 없이 그리는 숫자는 없다.** 모든 지표 응답이 그것을 달고 온다(§3-3).
- 기준 시각이 하루를 넘으면 **눈에 띄게** 적는다.
- pull 실패 사유를 **그대로** 보여 준다(권한·네트워크·저장소). 「실패했습니다」만 적으면
  사용자가 할 수 있는 일이 없다.

## 9. 남은 결정 (운영자)

| # | 질문 | 왜 지금 정해야 하나 |
|---|---|---|
| ① | **팀이 같은 숫자를 봐야 하나?** | 「아무것도 안 나간다」면 **각자 자기 PC 의 숫자**를 본다. 각자 pull 시각이 달라 숫자도 다를 수 있다. 같아야 한다면 집계가 어딘가로 나가야 하고, 그건 다른 설계다 |
| ② | **무엇을 볼 건가?** (지표 목록) | §8 의 1번. 이게 없으면 나머지를 못 만든다. 「SQL 로 직접 파는 것」이면 에이전트 대신 `duckdb -ui` 로 끝난다 |
| ③ | **회사가 Chrome 정책을 밀 수 있나?** (`LocalNetworkAccessAllowedForUrls`) | 있으면 권한 프롬프트가 사라진다. 없으면 각자 한 번 누른다 |
| ④ | **Apple Developer 계정이 있나?** (연 $99) | 없으면 macOS 사용자는 새 버전마다 「시스템 설정 → 그래도 열기 → 관리자 암호」 |
| ⑤ | **바이너리를 어디에 두나?** | 우리 콘솔은 무료 인스턴스(512Mi)라 수십 MB 를 얹으면 배포 zip 과 메모리에 그대로 얹힌다. **GitHub Releases** 를 권한다 |
| ⑥ | **그 폴더를 어떻게 clone 했나?** | 자동 pull 이 그대로 될지가 여기서 정해진다. 자격 증명은 **에이전트에 안 넣는다** |
| ⑦ | **Safari 를 쓰는 사람이 실제로 있나?** | 없으면 §4-4 의 폴백 화면(항목 3)을 안 만들어도 된다 |
