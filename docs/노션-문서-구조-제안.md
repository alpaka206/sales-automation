# 노션 문서 구조 제안 (AI 회신 초안용)

> 노션 관리자에게 보여주기 위한 문서입니다.
> **현재 「B2B 리드 대응 정책」 구조는 그대로 두고**, 아래 세 가지만 지키면 AI가 읽는 정확도가
> 크게 올라갑니다. 페이지를 새로 만들거나 옮길 필요는 없습니다.

---

## 0. 지금 어떻게 동작하는지 (30초)

```
노션 ──(담당자 PC가 읽음)──▶ HTTPS ──▶ 서버 ──▶ DB 사본 ──▶ AI 회신 초안
```

- 서버는 노션을 직접 못 읽습니다(회사 노션이라 API 토큰 발급 불가). 그렇다고 담당자 PC가 대신
  할 수도 없습니다 — 사내망이 DB 포트를 막고 있어서 PC는 DB에 쓰지 못합니다. **노션을 읽을 수
  있는 기계와 DB에 쓸 수 있는 기계가 서로 다릅니다.**
- 열려 있는 길은 **담당자 PC → 서버 HTTPS** 하나입니다. 그 위로 잇습니다: PC가 노션을 읽고,
  읽은 내용을 서버로 올리고, 서버가 DB에 씁니다.

**갱신하는 방법 (둘 중 편한 쪽)**

1. **`노션 동기화.bat` 더블클릭** — 등록된 문서를 전부 읽어 서버로 올립니다.
   (`.env` 에 `NOTION_TOKEN_V2` 가 있으면 그냥 더블클릭, 없으면 Export zip 을 아이콘에 드롭)
2. **콘솔에 zip 업로드** — `이메일 템플릿 → 정책 문서 → 노션 Export 올리기`.
   PC에 아무것도 설치하지 않아도 되고, 노션을 볼 수 있는 사람이면 누구나 할 수 있습니다.
- **AI는 DB 사본만 봅니다.** 노션을 고쳐도 동기화 전까지는 반영되지 않고, 반대로 노션이
  잠깐 안 열려도 회신은 계속 나갑니다.
- **올린 zip 에 있는 문서가 곧 목록입니다.** 노션에서 자식 페이지를 새로 만들었으면, 다음에
  내보낼 때 `Include subpages` 만 켜져 있으면 됩니다 — 처음 보는 문서는 `문의별 참고`로
  자동 등록됩니다. 콘솔에서 URL 을 손으로 넣을 필요가 없습니다.
- **지우는 것은 자동이 아닙니다.** zip 에 없다고 사라진 것으로 보지 않습니다 (한 페이지만
  내보냈을 수도 있으니까요). 폐기는 콘솔의 `삭제` 버튼으로 사람이 합니다.

## 1. 문서는 두 종류뿐입니다

등록할 때 둘 중 하나를 고르게 되어 있습니다. 이 구분이 정확도의 대부분을 좌우합니다.

| 구분 | 뜻 | 예 |
|---|---|---|
| **항상 적용** | 모든 회신에 무조건 들어감 | 공통 원칙, 가드레일, 톤앤매너, 한국 IP 고객 응대 |
| **문의별 참고** | 그 문의에 해당할 때만 들어감 | 지원 언어, 크레딧 차감, B2B 플랜 기능, 견적·가격 |

**왜 중요한가**: `항상 적용`이 늘어날수록 모든 회신이 길어지고 느려지며, 정작 중요한 규칙이
묻힙니다. 지금 기준으로 `항상 적용`은 **2~3개**가 적당합니다.

현재 문서 기준 권장 분류:

**항상 적용**
- `B2B 리드 대응 정책` (§2 공통 원칙 + §2-4 가드레일)
- `한국 IP 고객 응대`

**문의별 참고**
- 견적·가격 / 전반적 소개 / B2B 플랜 기능 / 지원 언어 / 크레딧 차감 방식 / CS 응대 정책

## 2. 지켜 주시면 좋은 세 가지

### ① 한 페이지 = 한 주제

AI는 문의 내용을 보고 **필요한 페이지만 골라** 읽습니다. 한 페이지에 여러 주제가 섞여 있으면
"이 페이지가 필요한가"를 판단하지 못해, 통째로 넣거나 통째로 빠집니다.

- 좋음: `지원 언어` 페이지에는 언어 목록만
- 나쁨: `지원 언어` 페이지 안에 가격표와 환불 규정까지

### ② 자식 페이지는 부모에 내용을 요약해 주세요

지금 정책 문서처럼 `mention-page` 링크로 자식을 가리키는 구조는 좋습니다. 다만 **AI는 링크를
따라가지 않습니다** — 등록된 페이지 각각을 따로 읽을 뿐입니다.

그래서 부모 페이지의 표에 있는 **「설명」 칸이 실제로 중요합니다.** 지금처럼
"참고 문서 속 B2B 플랜별 적합 기준에 따라 맞춤형 플랜을 찾은 후, 4가지 케이스에 따라 작성"
같은 한 줄이 있으면 AI가 그 문서를 어떻게 쓸지 압니다. 계속 그렇게 써 주세요.

### ③ 표와 목록을 쓰세요, 줄글보다 훨씬 정확합니다

노션 표는 그대로 읽힙니다. "A는 X, B는 Y" 같은 대응 관계는 문단보다 표가 압도적으로 정확합니다.
지금 §1과 §3의 표 형식이 딱 좋습니다.

## 3. 페이지를 새로 만들거나 링크가 바뀔 때

| 상황 | 노션에서 | 콘솔에서 |
|---|---|---|
| 새 참고 문서 추가 | 페이지 만들기 | **아무것도 안 해도 됨** — 다음 zip 에 담기면 자동 등록 |
| 내용 수정 | 노션에서 수정 | Export 받아 **다시 드롭** |
| 페이지 링크 변경 | — | **아무것도 안 해도 됨** — 문서는 링크가 아니라 페이지 ID 로 따라갑니다 |
| 문서를 잠시 빼고 싶음 | 그대로 둠 | `중지` 버튼 (등록과 사본은 남음) |
| 문서 폐기 | 노션에서 삭제 | `삭제` 버튼 |

> **글은 노션에서만 쓰십시오.** 콘솔에서 하는 일은 두 가지뿐입니다 — 어떤 페이지를 읽을지
> 등록하는 것, 그리고 Export zip 을 올려 사본을 갱신하는 것.

---

## 4. 아직 문서가 없어서 AI가 답하지 못하는 것들

현재 정책 문서를 기준으로 보면, 아래 질문이 오면 **문서에 없다고 판단해 "검토 필요"로 넘깁니다.**
자주 온다면 페이지를 만들어 주시면 좋습니다.

- **납기 / 소요 기간** — "200시간이면 얼마나 걸리나요"
  (§2-4가 해결 시점 확답을 금지하므로, 확답이 아닌 *일반적 범위*를 적어 주시면 답할 수 있습니다)
- **보안 / 데이터 처리** — 업로드한 영상 보관 기간, 학습 사용 여부, NDA·DPA 가능 여부
  (엔터프라이즈 문의에서 거의 반드시 나옵니다)
- **결제 조건** — 세금계산서, 해외 송금, 선불/후불, 통화
- **품질 보증 / 재작업** — 결과가 기대와 다를 때의 절차
- **샘플 / 파일럿** — 계약 전 샘플 제작 가능 여부와 조건

각각 한 페이지, `문의별 참고`로 등록하면 됩니다.

---

## 5. 요약 — 관리자가 기억할 것

1. **글은 노션에서만.** 고친 뒤 Export zip 을 콘솔에 올리면 반영됩니다.
2. **Export 할 때 `Include subpages` 와 `Create folders for subpages` 를 켜세요.** 자식 문서가 담기고, 표가 올바른 페이지에 붙습니다.
3. **`항상 적용`은 2~3개로 유지.** 나머지는 전부 `문의별 참고`.
4. **한 페이지 = 한 주제**, 표와 목록 위주로.
