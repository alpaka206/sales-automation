# 호스팅·배포 아키텍처 결정 (무료 운영 기준)

> 한 줄 요약: **인바운드는 Render(Python 컨테이너, 슬립-후-깨어남)에서 24h 대응, 아웃바운드는 소스에 따라 Render(API 소스) 또는 로컬 워커(크롤링)에서, DB/LLM/승인은 무료 스택으로.** Cloudflare Workers·Vercel 같은 서버리스에는 올릴 수 없다.

## 배경 / 목적

"완전 무료 + 카드 없이 + 실서비스"로 운영하려는데, 어디에 배포해야 하는지(Render vs Cloudflare vs Vercel vs 자체 PC)와 그 이유를 한 곳에 정리한다.

---

## 1. 결론

| 구성요소 | 선택 | 비용 |
|---|---|---|
| 앱 실행(인바운드 24h + API 아웃바운드) | **Render Free** (Python 컨테이너) | $0 (슬립 있음) |
| DB | **Supabase Postgres** (무료) | $0 |
| LLM | **Gemini** (Vertex 서비스계정 또는 API 키) | 거의 $0 |
| 이메일 발송 | HubSpot(기본) 또는 Gmail SMTP | $0 |
| 승인 | **Slack + 웹 UI** | $0 |
| 크롤링 아웃바운드(LinkedIn·잡보드) | **로컬 워커 PC** 또는 원격 브라우저(CDP) | $0 |
| 앞단(도메인·TLS·WAF) | **Cloudflare** (Render 앞에) | $0 |

핵심: **Cloudflare/Vercel은 호스팅 후보가 아니라, Cloudflare는 Render "앞단"으로만 쓴다.**

## 2. 왜 Cloudflare Workers·Vercel에 못 올리나 (서버 vs 서버리스)

이 앱은 **"상시 떠 있는 서버"**(uvicorn FastAPI)이고, Workers/Vercel은 **"요청 오면 잠깐 도는 함수"**다. 그릇이 다르다.

### 2-1. 런타임/라이브러리 — 코드 자체가 안 뜸
Workers는 V8 아이솔레이트(JS, 또는 Python=Pyodide/WASM). 이 앱의 네이티브 의존성이 WASM/아이솔레이트에서 안 돈다:

| 의존성 | 용도 | 서버리스에서 |
|---|---|---|
| **psycopg2** | Postgres C 드라이버(libpq) | ❌ WASM 불가 |
| **google-genai** | Gemini (grpc/auth) | ❌ 네이티브 의존성 |
| **Playwright** | 진짜 Chromium 실행 | ❌ 서브프로세스/메모리 불가 |

### 2-2. "이벤트 기반이면 서버리스로 되잖아?" 에 대한 답
웹훅이 이벤트 기반인 건 맞다. 하지만:

- 웹훅은 **1~2초 안에 200 OK**를 줘야 한다(HubSpot은 오래 걸리면 실패로 보고 재시도).
- 인바운드 처리는 분류→점수→문서라우팅→**pro 초안**까지 **20~40초** 걸린다.
- **서버(Render)**: 웹훅에 **즉시 200 응답**하고 무거운 LLM 작업은 **백그라운드로 계속** 처리 가능(프로세스가 살아있으므로).
- **서버리스 함수**: **응답을 반환하는 순간 함수가 죽는다.** 그래서 40초 작업을 응답 전에 다 끝내야 하고 → 함수 시간제한 초과 + HubSpot 타임아웃.

→ **이벤트 기반 ≠ 서버리스 가능.** "응답 따로, 작업 따로"가 되려면 서버여야 한다.

### 2-3. Vercel도 같은 범주
Vercel Python = 서버리스 함수(Lambda식). CPython은 Workers보다 잘 되지만 **함수 실행시간 제한 + 상시/백그라운드 없음 + Playwright 불가 + Dockerfile 못 씀(재작성 필요)**. → Render보다 손해.

### 2-4. Cloudflare Containers(2025)
Docker를 돌리니 이론상 가능하나 **베타 + Workers 유료플랜 필요** → 무료 아님, 제외.

## 3. "항상 켜진 서버"가 필요한가? → 인바운드엔 아니다

- 인바운드 웹훅은 **올 때 깨어나서 응답**하면 된다 → **Render Free(슬립 후 깨어남)로 충분**. 첫 요청 ~30초 콜드스타트는 **HubSpot 재시도**가 흡수.
- **승인 시 즉시 발송**(`SEND_WORKER_ENABLED=false`)이라 발송용 상시 워커도 불필요. 승인 클릭이 서버를 깨우고 그 안에서 발송.
- **진짜 주기 실행이 필요한 건 자동 팔로업(`reply_check`)뿐** → **외부 무료 cron**(cron-job.org·UptimeRobot·GitHub Actions)이 `/run/reply_check`를 하루 1~2회 호출.

권장 Render 설정:
```
SEND_WORKER_ENABLED=false      # 승인 시 즉시 발송
INBOUND_POLL_ENABLED=false     # 웹훅 수신
PUBLIC_BASE_URL=https://<서비스>.onrender.com   # Slack 승인 링크용
```

(슬립이 싫으면) keep-warm 핑으로 `/healthz`를 ~14분마다 호출 → 사실상 안 자게 유지(무료 750시간 내).

## 4. 아웃바운드: 소스별로 갈린다

아웃바운드는 한 덩어리가 아니라 **소스에 따라** Render 무료 가능 여부가 다르다.

| 소스 | 브라우저 필요 | Render Free | 어디서 |
|---|---|---|---|
| YouTube (Data API) | ✗ | ✅ | Render |
| Google 검색 (CSE API) | ✗ | ✅ | Render |
| 수동/LinkedIn CSV | ✗ | ✅ | Render |
| 잡보드(사람인/잡코리아) | ✓ Playwright | ❌(512MB) | 로컬 워커 또는 원격 브라우저(CDP) |
| LinkedIn 크롤링 | ✓ Playwright | ❌ | 로컬(가정용 IP) — 데이터센터 IP는 차단·계정정지 위험 |

- 회사 홈페이지 자동요약(enrichment)도 Playwright지만 **실패해도 메일은 생성**(Render에선 자동 스킵).
- **결과는 어디서 돌리든 같은 Supabase에 저장** → Render 클라우드 앱 대시보드에서 동일하게 보임.

### 크롤링을 무료 서버에서 돌리는 대안 (선택)
- **원격 브라우저(CDP)**: 코드의 `launch` → `connect_over_cdp`로 바꿔 외부 브라우저(Steel.dev 100h/월, Browserless 등 무료/무카드)에 접속 → Render Free에서도 크롬 없이 크롤링. 잡보드엔 적합.
- **GitHub Actions**: 무료 러너에서 Playwright 실행, `workflow_dispatch`로 트리거 → 결과 Supabase 저장.
- **LinkedIn만 예외**: 데이터센터 IP 차단 + 계정정지 위험 → 로컬(가정용 IP)·소량·쿠키 권장. 스텔스 라이브러리도 지문만 가릴 뿐 IP/계정/행동/레이트리밋은 못 가림.

---

## 5. Cloudflare의 올바른 역할 = 앞단

호스팅 대신 **Render 앞에** 둔다: 커스텀 도메인 + 무료 TLS + CDN + **WAF·DDoS·봇 차단**(공개 웹훅 보호). 즉 **Render(실행) + Cloudflare(앞단)** — 경쟁이 아니라 보완.

## 6. 배포 절차 요약

1. (선행) 코드 GitHub에 푸시 — 완료(Private: `alpaka206/sales-automation`).
2. Render → New → **Blueprint** → 저장소 연결(`render.yaml` 자동 인식).
3. 환경변수(대시보드): `DATABASE_URL`, `HUBSPOT_PRIVATE_APP_TOKEN`, `GOOGLE_CREDENTIALS_JSON`(또는 API 키), `SLACK_BOT_TOKEN`+`SLACK_APPROVAL_CHANNEL_ID`(또는 `APPROVAL_CHANNEL=none`), `PUBLIC_BASE_URL`, `SEND_WORKER_ENABLED=false`, `INBOUND_POLL_ENABLED=false`.
4. 배포 → `init_db.py`가 마이그레이션 자동 적용.
5. 검증: `/healthz`, 웹 UI(`/knowledge`·`/messages`), HubSpot 웹훅 URL 등록 `…/webhook/hubspot/inbound`.
6. (선택) 자동 팔로업용 외부 cron, 크롤링용 로컬 워커.
