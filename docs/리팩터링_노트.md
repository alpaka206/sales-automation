## 테스트 품질 수정 (기존 결함)

`main` 에서도 실패하던 **환경-결합 브리틀 테스트 2건**을 결정적으로 수정(리팩터와 무관):
- `test_reply_check`: `FOLLOWUP_AFTER_DAYS` 를 테스트 내에서 고정(`.env` 값 의존 제거).
- `test_inbound_flow::test_inbound_enriched_from_hubspot`: `INBOUND_DOMAIN_ENRICHMENT_ENABLED=False` 로 고정(classify 호출 인덱스 가정이 도메인 enrichment LLM 호출로 깨지던 문제).

결과: **598 passed, 1 failed**. 남은 1건은 로컬 venv 에 `google` 패키지 미설치로 인한 환경 의존 테스트(`test_protected_route_accepts_valid_token`)뿐 — 배포 환경에선 무관. 회귀 0.

## 의도적으로 보류한 것: `src/api/web/routes.py` (약 759줄)

가장 긴 파일이지만 **이번엔 분할하지 않음.** 이유:

- 테스트들이 이 모듈의 내부 심볼을 **모듈 속성으로 직접 패치**한다: `src.api.web.routes._dashboard_context`, `_message_detail_context`, `_messages_list_context`, `_settings_context`, `SessionLocal`, `_reset_kb_cache` 등(test_web_ui, test_settings_page, test_knowledge_routes, test_outbound_routes, test_icp_rules, test_unsubscribe).
- 패키지로 분할하면 핸들러가 서브모듈로 이동하면서 위 패치들이 더 이상 핸들러에 영향을 주지 못해 **6개 테스트 파일의 패치 경로(약 20곳)를 함께 수정**해야 함 → 한 번에 안전하게 끝내기엔 회귀 위험이 큼.

### 추후 분할 계획(권장)
`routes/` 패키지로 분할 + 테스트 패치 경로 갱신:
- `routes/_shared.py`(templates, esc, 상수)
- `routes/dashboard.py` / `messages.py` / `knowledge.py` / `icp.py` / `outbound.py` / `settings_page.py` / `unsubscribe.py`
- `routes/__init__.py` 가 서브 라우터를 `router` 로 합침
- 서브모듈 상대 import 깊이는 **4단계(`from ....common.config import settings`)** 주의
- 각 테스트의 `src.api.web.routes.X` 패치를 `src.api.web.routes.<서브모듈>.X` 로 갱신
- (권장) 장기적으로는 테스트가 내부 컨텍스트 빌더를 패치하지 않도록 의존성 주입으로 전환하면 결합이 풀림
