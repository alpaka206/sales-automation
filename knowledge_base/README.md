# knowledge_base/

회사 안내 자료(요금제·정책·제품 설명·FAQ 등)를 **마크다운 파일**로 보관하는 곳입니다.

인바운드 문의가 들어오면 LLM이 메시지를 먼저 **카테고리로 분류**하고, 이 폴더에서 **해당 카테고리에 해당하는 문서만 골라** 답장 초안 작성 프롬프트에 함께 넣습니다.

예: 고객이 "월 사용료가 얼마인가요?"라고 물어보면 → `pricing_question`으로 분류 → `categories`에 `pricing_question`이 들어 있는 .md 파일들만 LLM에 함께 전달.

## 파일 형식

```markdown
---
title: 2026 요금제
categories: [pricing_question, purchase_inquiry]
---

# 본문 시작

요금제 내용을 자유롭게 작성하세요.
표, 목록, 코드블록 다 사용 가능합니다.
```

### frontmatter 필드

- `title` *(선택)* — 사람이 보기 좋은 제목. LLM 프롬프트에도 같이 들어갑니다.
- `categories` *(권장)* — 어떤 인바운드 분류에서 이 문서를 참조할지 지정.
  - 가능한 값: `purchase_inquiry`, `partnership`, `pricing_question`, `support`, `recruiting`, `other`
  - 모든 카테고리에서 항상 참조하고 싶으면 `[all]` 하나만 적으면 됩니다.
  - **`categories`를 생략하면 `[all]`로 간주**합니다 (간단한 문서를 빠르게 추가할 때 편의).

`spam`은 매칭에서 제외됩니다 (스팸 답장에는 회사 자료가 필요 없음).

## 작성 팁

- **파일을 잘게 나누세요.** "요금제.md" 하나에 모든 걸 욱여넣지 말고, "스타터플랜.md", "엔터프라이즈요금.md" 식으로 쪼개면 LLM이 관련 문서만 추려서 인용하기 좋습니다.
- **사실만 적으세요.** 톤·금지어 같은 규칙은 [company_rules/](../company_rules/)에 두세요. 여기는 "무엇"이 들어가는 곳이고, company_rules/는 "어떻게 말할지"가 들어가는 곳입니다.
- **숫자·날짜는 명시적으로.** "최근 인상된 가격"보다 "2026년 1월 인상된 가격" 식으로 명시하면 LLM이 잘못 인용하지 않습니다.
- **한국어/영어 자유.** 메시지 언어에 맞춰 LLM이 알아서 인용·번역합니다.

## 변경 반영

- 파일을 수정하면 다음 LLM 호출부터 즉시 반영됩니다 (프로세스 단위 캐시 — BE 재시작 권장).
- 파일을 추가/삭제할 때도 마찬가지.
